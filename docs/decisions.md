| 2026-10-01 | s5, s11, s12 (implementation of) | Agent tool calls use a JSON text protocol, not the provider's native function calling. Thinking is disabled for the baseline (`thinking_budget = 0`) and `thoughts_token_count` is recorded anyway. Malformed agent output gets exactly one repair attempt, counted in `retries` and reflected in `output_validation`. A trial with no parseable answer is written through `no_answer_row()` with `actual_status = "NO_ANSWER"`. | Native function calling would have the provider validate tool names and argument shapes, which makes safety check S6 ("no unauthorized tool and no malformed tool arguments") unobservable: the agent could not attempt a violation even if it tried, so a real failure mode would be hidden instead of counted. The text protocol also keeps the prompt portable across model families, which Experiment C needs. Thinking is disabled because internal reasoning tokens are never returned, so hidden reasoning would leave the s14 Layer 4 trajectory evaluation blind to most of what the model did and would understate `output_tokens`; recording the reported thinking-token count means a provider default changing underneath us becomes visible in the data. One repair attempt, counted, keeps a formatting slip distinguishable from a reasoning failure without hiding how often the output contract is broken. `NO_ANSWER` exists because defaulting an unparseable response to a real status would score a total agent failure as a correct answer on any case whose expected status happened to match the default. | n/a (no LLM trial executed yet) |
| 2026-10-02 | s6.3, s7, s12 (trace schema 1.0 -> 1.1) | Four corrections forced by the first live run. (1) The runner never passed the trace to `to_row`, so every tool, trajectory and token metric recorded zero for successfully evaluated trials; fixed. (2) Added `OutputValidation.NOT_PRODUCED` and bumped the trace schema to 1.1. (3) Per-day quota rejections are now detected from the returned `quotaId` and raised immediately as `DAILY_QUOTA_EXHAUSTED` with no retry, while per-minute rejections honour the provider's `retryDelay` hint up to the configured cap. (4) The runner stops the sweep when the daily quota is exhausted and labels the report an incomplete run; it also reports model requests per trial. | (1) A silent zero is worse than a missing value: the first run reported `num_tool_calls = 0` for a trial whose trace held ten tool calls, which would have made the whole of Layer 3 and Layer 6 look empty rather than broken. (2) The run recorded a trial killed by a quota rejection as `valid` output when no output existed at all; `unparseable` would have been equally false, since nothing was ever offered to parse, and it would have charged an infrastructure failure to the agent. (3) A per-day budget cannot be waited out inside a run, so backing off against one spends a minute per trial to collect an identical rejection; the observed limit was 20 requests per day for `gemini-2.5-flash`. (4) Continuing a sweep past an exhausted daily quota produces one void row per remaining case; stopping keeps what was measured and prevents the partial result being read as a dataset-wide one. Requests per trial is reported because on a free tier the binding constraint is the request cap, not wall clock. | n/a (the only live run so far is the Milestone 1 machinery shakedown, which is not a reported result) |
| 2026-10-02 | s6.4 | Baseline model changed from `gemini-2.5-flash` to `gemini-2.5-flash-lite`. `gemini-2.5-flash` becomes the Experiment C fallback comparator. Added a measured request-budget subsection to s6.4 and restated the s7 runtime gate in requests rather than wall clock. | The first live run measured the Flash free-tier cap at 20 requests per day, against roughly ten model requests per trial, which is two trials per day: Milestone 1 would take a week and the full matrix would need about 5,250 requests per configuration. | 2026-10-02 | s6.3, s6.4 | Baseline model changed again, from `gemini-2.5-flash-lite` to `gemini-3.5-flash-lite`. Added a `MODEL_UNAVAILABLE` failure class that is never retried, and a one-request preflight check in the runner that aborts before the sweep if the configured model is not callable. | `gemini-2.5-flash-lite` is returned by `models.list` for this key and yet answers every request with 404: "This model is no longer available to new users." A model can therefore be advertised as available and still be closed, which is the hosted-provider reproducibility risk recorded in s6.3 item 1 showing up within a day of adopting the provider, and in the most visible possible form rather than as silently changed weights. It is worth noting in the write-up: the migration notice names a successor model, so the provider treats the substitution as routine. Without the new failure class the 404 was reported as a generic provider error and the sweep continued, producing one void trial per case; the preflight spends one request to avoid that. | n/a (no reported result exists yet) |
| 2026-10-02 | s6.2, s6.3, s12 (trace schema 1.1 -> 1.2), s23 (results schema 1.1 -> 1.2) | Replaced `thinking_budget: 0` with `thinking_level: MINIMAL`. Added `thinking_level` to the run config and `thinking_tokens` to trace events, trace totals and trial rows; `total_tokens` now includes them. Added `scripts/diagnose_model.py`, which probes one generation parameter per request and reports what a model accepts. | A 400 INVALID_ARGUMENT on the first `gemini-3.5-flash-lite` preflight gave no indication of which argument was invalid, so the parameters were probed one at a time. `thinking_budget` is rejected by Gemini 3.x; `thinking_level` is accepted and its enum floor is MINIMAL, so internal reasoning can be reduced but not switched off. The earlier plan to disable thinking is therefore not available, and that is a real limit on Layer 4 rather than a configuration detail: part of each trial's deliberation is charged, never returned, and invisible to the trace. Recording the thinking-token count quantifies the hidden portion instead of ignoring it, and including it in `total_tokens` keeps the efficiency layer honest. Probing by request rather than reading documentation was necessary because the only authority on what this key may send is the API. | n/a (no reported result exists yet) |
| 2026-10-02 | s6.3 (implementation of) | Disabled automatic function calling (`automatic_function_calling.disable = True`) and set `response_mime_type = "application/json"` without a `response_schema`. Empty-text responses are now retried like other transient failures before being raised as `EMPTY_RESPONSE`. | The first live run against `gemini-3.5-flash-lite` returned `finish_reason = MALFORMED_FUNCTION_CALL` with empty text on 3 of 8 requests: the model tried to emit a native function call even though the agent speaks a JSON text protocol and no tools were declared to the SDK. An empty response is a provider outcome, not an agent answer, and is not deterministic, so retrying it before failing the trial is more honest than charging the agent for it. `response_schema` was deliberately not set alongside the mime type: a schema would have the provider enforce the output shape, which is exactly the behaviour section 11 needs the agent to be measured doing for itself, so forcing shape at the API layer would quietly remove the "malformed or repaired output" result from what the experiment can observe. | n/a (no reported result exists yet) |
| 2026-10-02 | agent.max_steps, Appendix C | Resolved O-3: `max_steps` raised from the provisional 12 to 20. | The first live Milestone 1 run produced a trace (DOC-0002, run `baseline_v1-20261001T184634Z`) that used all 12 steps on legitimate tool calls — 6 `lookup_policy` calls (one a wasted guess at a nonexistent rule_id) and 5 section reads, with one correctly-flagged redundant call — and was still exploring, not looping, when the cap ended the trial with no final answer. That is a real `max_steps` shortfall, not an agent defect, so the budget is raised rather than the behaviour investigated further. 20 gives roughly 1.5x headroom over the observed need across one case; it is not re-tuned per case, since a fixed cap is part of what section 14's trajectory evaluation measures against. | DOC-0002 in the baseline run that produced it must be re-run before being reported; its `max_steps` trial is void under the old cap, not a true `NO_ANSWER`. |
